# 迁移阶段与验收

## 版本与支持

| 版本 | 状态 |
| --- | --- |
| 1.0.0–1.6.1 | 历史基线，只保留标签与更新日志 |
| 2.0.0 起 | 正式发版，Composer 包 `fxri/fxyin`，要求 PHP 8.2 起 |

2.0 不保留 API 兼容层：门面层与全局函数移除、点分模式号改为具名枚举、六元响应数组改为五键信封、安装方式改为 Composer。过渡层只能在接入项目内自建。

## 升级前的四件事

| 事项 | 说明 |
| --- | --- |
| PHP 版本 | 以实际部署版本为准，`composer.json` 里的旧约束可能已过时；低于 8.2 先做 PHP 升级，不与框架升级混在一起 |
| Composer | 2.0 只通过 Composer 分发，没有 `composer.json` 的项目先补接入 |
| 可回退 | 保留 1.x 目录、部署包与数据库快照，入口保留切换开关 |
| 框架副本可复原 | 1.x 的 `extend/fxri/base` 常被就地改过，升级前逐文件比对备份，导出本地改动清单，凡 1.6.1 没有的方法或行为都要先定落点 |

## 路线选择

```text
PHP < 8.2 ─────────────── 是 → 先完成 PHP 升级，再回到本指南
没有 Composer ─────────── 是 → 先补 composer.json 与自动加载
旧 API 小于 100 处 ────── 是 → 路线 S：直接改造
旧 API 100–500 处 ─────── 是 → 路线 M：过渡门面 + 分域替换
旧 API 大于 500 处 ────── 是 → 路线 L：过渡门面 + 基线收敛 + 双跑
```

| 路线 | 做法 | 退出条件 |
| --- | --- | --- |
| S 直接改造 | 删除旧目录，接 Composer 2.0，逐文件替换旧调用 | 全仓旧命名空间与点分模式号归零 |
| M 过渡门面 | 项目内保留旧命名空间做适配层，内部改调 `Fxri\*`，按能力域替换 | 适配层调用量持续下降并归零 |
| L 过渡门面 + 基线 | 在 M 基础上按目录设基线，超限即失败；关键接口新旧响应双跑比对 | 基线归零、双跑差异清零 |

三条路线的终点一致：删除过渡层，业务代码直接用 `Fxri\*` 与 `Kernel`。

## 八个阶段

| 阶段 | 目标 | 退出条件 |
| --- | --- | --- |
| 0 体检与基线 | 生成项目画像、统计旧 API、记录基线 | 体检报告与基线文件入库 |
| 1 环境与依赖 | PHP 8.2、Composer、`fxri/fxyin:^2.0` | `composer install` 成功，自动加载可用 |
| 2 引导与装配 | 删除 1.x 框架副本，改用 `KernelBuilder` | 入口可启动，命令行或 HTTP 冒烟通过 |
| 3 配置 | 拆成纯数组与运行时服务 | 配置不再调用旧门面、不读超全局变量 |
| 4 扩展目录 | 处理门面扩展、工厂类、存储脚本、语言与函数 | 扩展目录只剩项目自有代码，旧注册项清零 |
| 5 代码分域 | 按配置、参数、SQL、数据、文本、文件、安全、HTTP 逐域替换 | 各域基线归零 |
| 6 响应与异常 | 内部用 `Envelope`，对外保持旧协议 | 新旧响应双跑一致，异常映射可用 |
| 7 验收与清理 | 删除过渡层、旧命名空间与旧目录 | 全量验收通过，回滚路径演练完成 |

各阶段的施工细节与勾选项见仓库 `docs/upgrade-2.0-checklist.md`；接入形态模板见 `docs/upgrade-2.0-runtime.md`；扩展目录逐项处置见 `docs/upgrade-2.0-extend.md`。

## 阶段要点

- 阶段 2：入口只保留 Composer 自动加载，不要同时保留旧 `autoload.php`；宿主容器已有绑定时走适配器，没有则在入口持有内核。
- 阶段 3：配置文件只 `return` 数组，路径拼接与请求态取值移到代码里；响应格式相关配置不再由配置文件驱动。
- 阶段 4：门面扩展方法迁入项目服务或过渡层，工厂类改为显式工厂或容器解析，语言词条作为纯数据迁入项目语言目录。
- 阶段 5：逐能力域替换，每完成一域跑一次基线，避免一次性大改。
- 阶段 6：响应键固定为 `code`、`message`、`data`、`extend`、`debug`；旧 `time` 需要时写入 `debug.time`；分页数据用四键壳。
- 阶段 7：先确认基线零新增，再删过渡层与旧目录。

## 验收

- `baseline --check` 零新增（任一目录高于基线即失败）。
- 全仓检索旧命名空间、`fxy_*` 全局函数、点分模式号，除迁移文档外归零。
- 旧响应数组的下标访问改为信封取值方法。
- 项目自身的聚合门禁命令全部通过；新旧响应双跑差异清零。
- 回滚演练完成：能切回旧入口，Composer 约束可退回 1.x。

## 回滚

- 升级前为 1.x 目录与部署包打快照；入口保留切换开关。
- 数据库与旧密文不必回滚：旧密文可由 `Security\DesCipher` 解密，不重写数据。
- 对外响应协议单独排期，框架升级不回滚协议变更。

## 红线

1. 不把 PHP 升级与框架升级放进同一次变更。
2. 不同时保留旧 `autoload.php` 与 Composer 自动加载。
3. 不在框架升级的同时修改对外响应协议。
4. 不把独立扩展模块计入本次迁移范围。
5. 不在多个接入仓库之间批量复制改动，先在小项目验证再推广。

## 常见卡点

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 入口 500，提示找不到类 | 两套自动加载并存，或旧引导仍被引用 | 删除旧引导，只保留 Composer |
| 配置加载报错 | 配置文件仍在调用旧门面或读超全局变量 | 按纯数组约束拆分 |
| 异常页输出堆栈 | 仍用旧异常输出方法或宿主默认处理器 | 改用统一异常映射 |
| 响应字段缺失 | 期望旧的 `time` 字段 | `time` 已并入 `debug`，由项目写入 |
| 门面方法找不到 | 扩展门面尚未迁入过渡层 | 补提供者或改为显式类 |
| 无 Composer 项目装不上 | 2.0 只通过 Composer 分发 | 先补接入 |
| 独立模块报错 | 误把它当成框架本体删除 | 保留原目录，单独排期 |
