## 背景

fxyin 的 `SkillInstaller` 生成的薄壳带 `<!-- fxyin-skill-entry: v1 -->`，判据同样只看标记版本：模板文案改了但不抬版本，重跑 `php vendor/bin/fxyin skills` 时会被判为「一致」而不重写，消费项目里的壳会长期停在旧文案。

## 实施方案

1. `src/Tooling/SkillInstaller.php`：marker 改两段式 `v1.1`（解析兼容旧 `v1`），壳正文与模板渲染结果逐字比对，不一致即重写。
2. `src/Tooling/SkillsCommand.php`：`fxyin skills --check` 扩展为「标记版本 + 正文逐字比对」双判据，正文不一致即报「壳正文与模板不一致，重跑 `php vendor/bin/fxyin skills` 补齐」并以非 0 退出。
3. 测试：`tests/Tooling/SkillInstallerTest.php` 增指纹守门——模板渲染结果变化而版本未变时用例失败，提示「请抬版本并刷新指纹」；补一条「旧 `v1` + 旧文案重跑即重写」的用例。
4. 抬版脚本：新增 `scripts/bump-skill-entry-version.mjs`（与 toolkit 的 `bump-entry-version.mjs` 同构）——模板指纹变化时 minor +1 并刷新测试指纹；major 由人显式改。
5. 接入 `scripts/verify.mjs`：加一步跑 `fxyin skills --check`（无壳项目自动跳过），使漂移在项目门禁内暴露。
6. 变更集：`pnpm changeset`（项目脚本包装 toolkit 的 release changeset）新建 patch。
