# CI 补手动触发与文档条件化

批次：本仓本轮门禁与 CI 收敛（前置：无）

## 背景

1. 两个工作流只有 `push` / `pull_request`，平台丢事件时无手动补跑入口。
2. 聚合门禁每次本地运行都全量构建文档站（含文档类型检查与内链检查），多数改动与文档站无关，属可省的时间。

## 实施方案

1. `.github/workflows/ci.yml`、`.github/workflows/deploy-docs.yml` 的 `on:` 下增加 `workflow_dispatch:`，附一行中文注释。
   - ⚠️ `deploy-docs.yml` 现有注释说明「站点输入不止 docs/，不设 paths 约束」，该策略保持不变，手动触发只是补一个入口。
2. `scripts/verify.mjs` 的文档站构建条件化：
   - 本地仅在改动触及 `docs/`、`CHANGELOG.md`、`README.md`、`package.json`、`pnpm-lock.yaml` 或传 `--full` 时执行；
   - CI 环境（`CI` 非空且非 0/false）恒执行；
   - 跳过时输出 `⊘` 行并写明原因，不静默。
3. 不改 CI 调用方式：PHP 矩阵仍传 `--skip-docs`（文档由部署工作流承担），`--skip-docs` 语义与优先级不变。
4. 不建变更集：CI 与本地门禁编排改动，用户不可感知。

## 影响范围

- 代码：`.github/workflows/ci.yml`、`.github/workflows/deploy-docs.yml`、`scripts/verify.mjs`。
- 无触达：`docs/` 手写页、`skills/`、`README.md`、`CHANGELOG.md`（本次不改内容）。
- 变更集：不建（用户不可感知）。

## 验证方式

- `node scripts/verify.mjs` 本地无文档改动时打印跳过原因；`node scripts/verify.mjs --full` 强制构建并通过。
- `CI=1 node scripts/verify.mjs --skip-code` 时文档步骤按 CI 口径执行（不被改动面裁剪）。
- `git diff` 确认工作流只新增触发器声明、门禁只新增条件判断。
- `node scripts/verify.mjs` 全绿（归档后复跑）。

## 实施结果

- 两个工作流各加 `workflow_dispatch:` 并附注释；`deploy-docs.yml` 的「不做 paths 过滤、每次推送全量重建」策略保持不变。
- `scripts/verify.mjs`：新增 `--full`、CI 判定与改动面判断（`git diff HEAD` + 未跟踪文件）；文档步骤按「docs/、CHANGELOG.md、README.md、package.json、pnpm-lock.yaml」判触发，跳过时输出 `⊘` 与原因；`--skip-code` 的跳过也补上了原因文案。
- 验证：本地无文档改动 → 文档步骤跳过；`CI=1` → 文档步骤执行；临时在 `docs/` 加文件 → 自动执行，删除后回落跳过；`--skip-code --full` 全绿。
