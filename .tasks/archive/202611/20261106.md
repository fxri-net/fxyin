# PHPStan 缓存隔离

## 一、背景

`composer check` 的两条静态分析（`stan` 与 `stan:deprecation`）各用一份配置，但都未声明 `tmpDir`，默认共用系统临时目录下的同一份结果缓存。串行执行时靠配置哈希区分尚且可用，一旦改为并发执行就会互相覆盖缓存文件：并发收益被折回冷分析，还可能带出缓存损坏提示。先做缓存隔离，后续并行化才有安全前提。

## 二、实施方案

批次：单批　计划位置：门禁并行化第 1 项　前置：无

1. `phpstan.neon`、`phpstan-deprecation.neon` 各声明独立 `tmpDir`（`.phpstan.cache/stan`、`.phpstan.cache/deprecation`）。
2. `.gitignore`、`.gitattributes`、`tools/check-package.php` 的 `EXPORT_IGNORED_PATHS` 同步登记 `.phpstan.cache`——发布包卫生检查强制导出排除双向一致，漏一处即失败。

## 三、影响范围

- 仅静态分析的结果缓存落点与打包排除登记；分析配置本身、检查项与判定规则不变。
- 不改 `src/`、`tests/` 与三处流水线配置。

## 四、验证方式

- `composer stan` 与 `composer stan:deprecation` 均通过，两个缓存目录各自生成。
- `php fxyin package` 通过（导出排除双向一致）。
- `pnpm verify` 全绿。

## 五、完成情况

- `phpstan.neon`、`phpstan-deprecation.neon` 各声明独立 `tmpDir`，两条分析分别落到 `.phpstan.cache/stan` 与 `.phpstan.cache/deprecation`。
- `.gitignore`、`.gitattributes`、`tools/check-package.php` 同步登记 `.phpstan.cache`，导出排除双向一致。
- 验证：`composer stan`、`composer stan:deprecation` 均无报错，两个缓存目录各自生成；`php fxyin package` 通过；`pnpm verify` 见提交前验收。
