# 信封extend对象化

> 计划位置：第 1 个（共 1 个）；前置：无；后继：无

## 背景

`Http\Envelope::toArray()` 当前把 `extend` 原样输出。空数组经 JSON 编码为 `[]`，与「固定五键、`extend` 为扩展对象」的契约不一致；配套 CLI 工具已按对象形态设计统一信封，跨栈消费方读到 `[]` 时无法按对象遍历。

本次把 `extend` 的 JSON 形态统一为对象：空值输出 `{}`，非空关联数组输出对象；PHP 侧 `Envelope::extend()` 仍返回 array，不改公开方法签名。

## 实施方案

1. `src/Http/Envelope.php`：`toArray()` 的 `extend` 改为 `(object) $this->extend`，空数组输出 `{}`，非空关联数组输出对象。`extend()` 方法签名与内部数组语义不变。
2. 明确边界：本次只改 `extend`；`debug` 现有「空数组转对象、非空原样」的行为不动。若后续要把 `debug` 的列表数组也统一为对象，另立任务。
3. 更新测试：
   - `tests/Http/EnvelopeTest.php`：`toArray()['extend']` 断言改为对象（`stdClass` 或 `(array)` 比较）。
   - `tests/Http/ResponderTest.php`、`tests/Integration/ThinkPHP/ExceptionHandlerTest.php`、`tests/Parity/MappingTest.php`：JSON 期望串 `"extend":[]` 改为 `"extend":{}`。
   - `tests/Http/XmlFormatterTest.php`：确认对象形态下仍输出 `<extend></extend>`。
4. 更新文档中所有 `extend` JSON 示例与字段说明：`docs/http.md`、`docs/http-api.md`、`docs/integration.md`、`docs/upgrade/` 下涉及 `extend` 的页面、`docs/adr/0001-v2-parity.md`、`docs/faq.md`。以 `rg '"extend":\[\]'` 与 `rg 'extend' docs` 定位，逐处确认。
5. 变更集：新增 `.changeset/extend-object.md`，bump `major`（公开 JSON 契约破坏性变更）；本次只落变更集，不执行版本号、CHANGELOG、标签与发布。
6. 不涉及 `JsonFormatter` / `XmlFormatter` 代码：对象由 `toArray()` 产出，XML 格式化器已有 `is_object` 到 `(array)` 的分支。
