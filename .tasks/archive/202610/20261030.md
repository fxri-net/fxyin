## 一、背景

项目里「名称 → 类」的注册表（如服务定位表）需要让 IDE 按字面量推导返回类型。PhpStorm 与 Intelephense 都读取 `.phpstorm.meta.php`，但该文件要求显式列出每个键，容易与运行时常量漂移。生成逻辑应作为框架能力提供，避免每个接入项目各写一份。

## 二、实施方案

1. 新增 `src/Tooling/MetaGenerator.php`：
   - `render(array $registries): string`：入参为「工厂方法 FQN => 名称映射数组」，输出 `.phpstorm.meta.php` 内容；
   - `check(string $file, array $registries): bool`：比对现有文件与映射是否一致；
   - 输出顺序稳定（按工厂方法名排序，键按映射数组原顺序），便于逐字节比对。
2. 新增 `docs/ide.md`：说明元数据只影响 IDE 补全、不参与运行；给出接入项目的最小脚本与 CI 校验方式。
3. 新增 `tests/Tooling/MetaGeneratorTest.php`：渲染结果、幂等、`check` 命中与不一致、空映射。

# 配置递归与扩展能力

批次：单批　计划位置：本轮第 1 项　前置：无

## 一、背景

接入方需要把 1.x 的嵌套配置（如 `facade/model.php`）原样迁入，而当前配置加载器只读取目录顶层的 `*.php`，导致项目侧只能摊平键位。另有两个兼容类以 `Legacy` 命名，不符合按能力命名的规范。

## 二、实施方案

1. `ConfigLoader` 支持递归子目录：相对路径去 `.php` 后转嵌套键（`facade/model.php` → `facade.model`），并兼容点号文件名（`third.oss.php` 等价 `third/oss.php`）；同层先文件后子目录、按名排序，后加载覆盖先加载；只接受纯数组。
2. `Envelope`、`Page` 补泛型注释：`Envelope<T>` 的 `data()` 返回 `T`，`Page<T>` 的 `records()` 返回 `list<T>`，`make()` 推导记录类型；不改运行签名。
3. `Security\LegacyCipher` → `Security\DesCipher`，`Security\LegacyToken` → `Security\DesToken`，同步引用与文档；类注释保留「用于读写 1.x 数据」的说明。

## 三、影响范围

- 配置加载顺序与键位推导；已有平铺配置行为不变。
- 仅注释与类名变化，运行行为不变。

2. 新增配置递归用例：嵌套目录、点号文件名、覆盖顺序、纯数组校验。
