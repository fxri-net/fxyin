计划位置：本轮第 1 项；前置：无。

## 背景

- `Client::param($param, $method)` 聚合 GET、POST、原始请求体与 CLI 入参，并支持按方法筛选、按数组提取。v2 的 `RequestContext` 只有方法、路径、头与原始体，没有入参聚合入口。
- `File::getList($path, $ext, $limit)` 递归列文件，支持 `|` 分隔的扩展名过滤与深度限制。v2 `Filesystem::listFiles()` 只列当前层，也没有扩展名过滤。
- `Param::pick($base, $data)` 按给定键提取，缺失键补 `null`；`Param\Picker::only()` 只保留已存在的键，语义不等价。

## 实施方案

1. 新增 `Http\RequestInput`：由 `RequestContext` 或全局变量构造，暴露 `query()`、`post()`、`body()`、`cli()`、`all()`、`get()`、`only()`。
2. `all()` 按查询串、表单、JSON 请求体、CLI 的顺序合并；请求体不是 JSON 对象时不参与合并，避免把不可用的字符串混入数组。
3. `only()` 走新增的 `Picker::pick()`，缺失键补 `null`，与 `Param::pick` 对齐。
4. `Filesystem` 新增 `findFiles()`：递归扫描、扩展名过滤、`maxDepth` 深度限制、结果排序；`listFiles()` 保持当前层语义不变。
5. 补测试：多来源合并、请求体解码、提取缺失键、递归深度、扩展名过滤、符号链接目录不跟随。
6. 更新对等快照与文档：`Client::param` → `Http\RequestInput`，`File::getList` → `File\Filesystem::findFiles`，`Param::pick` → `Param\Picker::pick`。

## 影响范围

`src/Http/RequestInput.php`（新增）、`src/File/Filesystem.php`、`src/Param/Picker.php`、对应测试、`docs/http.md`、`docs/file.md`、`docs/parity-1.6.1.md`、`tests/Parity/legacy-api.json`；不改变现有 `listFiles()` 与 `RequestContext` 行为。
