# 升级体检入口识别补遗

T5 回归时发现两处小问题：2.x 回溯样本的自有引导被报成「未识别」；`localOnlyMethods` 为空时 JSON 输出成数组而非对象，脚本侧容易误读。

计划位置：T5 回归中的修正项；前置：升级体检补强宿主框架识别（已完成）。

## 背景

- 1.x 原生项目的入口直接 `require extend/fxri/bootstrap.php`，这类项目不是 ThinkPHP、也不解析 `REQUEST_URI`，现有三条判定都不命中。
- `json_encode` 对空关联数组输出 `[]`、非空输出 `{}`，同一字段两种形态，消费方按对象遍历会读到数组自带属性。

## 实施方案

1. `detectFramework()` 在 ThinkPHP 各信号之后、自定义入口之前，增加 `extend/fxri/bootstrap.php` 被入口引用的判定，输出「风音 1.x 原生入口」。
2. 该判定要求两件事同时成立：`extend/fxri/bootstrap.php` 存在，且入口内容出现 `bootstrap.php`；避免 2.x 项目入口里出现包名时误判。
3. `localOnlyMethods` 为空时编码为对象（`stdClass`），与有值时保持同一形态。

## 影响范围

`tools/upgrade-inspect.php`、`tests/Tools/UpgradeInspectTest.php`。

## 验证方式

1. 新增用例：入口 `require extend/fxri/bootstrap.php` 的项目判为「风音 1.x 原生入口」。
2. 新增断言：无本地新增方法时 `localOnlyMethods` 为空数组（解码后）。
3. 2.x 项目不因入口提及包名被误判；ThinkPHP 与自定义入口样本结果不变。
4. `pnpm verify` 全绿。

## 完成情况

- 新增 `hasFxriBootstrap()`：`extend/fxri/bootstrap.php` 存在且入口引用 `bootstrap.php` 时判为「风音 1.x 原生入口」，排在 ThinkPHP 各信号之后、自定义入口之前。
- 2.x 回溯样本由此从「未识别」变为「风音 1.x 原生入口」；ThinkPHP、`core/start.php`、自定义入口样本结果不变。
- `localOnlyMethods` 为空时编码为对象，与有值时形态一致；补一条空值断言。
- `UpgradeInspectTest` 7 个用例、57 断言通过；`pnpm verify` 全绿。

> 负责人：唐启云　状态：已完成　范围：common　完成时间：2026-10-29 08:56

# 升级体检补强宿主框架识别

3 个 1.x 样本的宿主框架显示「未识别」，profile 因此缺少宿主上下文，路线建议只能靠体量档位。

计划位置：本轮第 4 项；前置：无。

## 背景

- 这些样本没有 composer.json 或没有 `thinkphp/` 目录，入口在根 `index.php`，现有检测只覆盖 Composer 依赖与 `thinkphp` 目录两种信号。
- 同一批样本中有 2 个非 ThinkPHP 项目（`core/start.php`），需要保证补强后不会把它们误判为 ThinkPHP。

## 实施方案

排查结论（先于实现）：3 个「未识别」样本的根入口是手写路由——直接解析 `REQUEST_URI`、`include` 站点级 `include/config.php`，既无 `think`、`thinkphp/`，也无 `vendor/topthink/framework`；它们的 `app/` 是项目自有目录。因此正确结论是「非 ThinkPHP（自定义入口）」，而不是 ThinkPHP。

1. 新增 `hasCustomEntry()`：读取 `index.php` 与 `public/index.php`，出现 `REQUEST_URI` 或 `include($_SERVER['DOCUMENT_ROOT']…)` 即判为手写路由。
2. 检测顺序保持：Composer 锁定 → `core/start.php` → `think` → `thinkphp/` → `vendor/topthink/framework` → 自定义入口 → 未识别；ThinkPHP 信号优先，避免误判。
3. 不臆造版本号：拿不到版本时仍输出「ThinkPHP（未锁定版本）」。

## 影响范围

`tools/upgrade-inspect.php`、`tests/Tools/UpgradeInspectTest.php`。

## 验证方式

1. 新增用例覆盖手写路由入口，断言 `非 ThinkPHP（自定义入口）`。
2. 3 个原先未识别的样本不再显示「未识别」。
3. `core/start.php` 样本仍判非 ThinkPHP，ThinkPHP 样本不受影响。
4. `pnpm verify` 全绿。

## 完成情况

- 新增 `hasCustomEntry()`，识别入口里的 `REQUEST_URI` 与 `include($_SERVER['DOCUMENT_ROOT']…)`；检测顺序排在 ThinkPHP 各信号之后，避免误判。
- 3 个原先「未识别」的样本输出「非 ThinkPHP（自定义入口）」；`core/start.php` 样本与 ThinkPHP 样本结果不变（分别为「非 ThinkPHP（core/start.php）」「ThinkPHP dev-master」）。
- 新增 `testProfileOfCustomEntryProject`，`UpgradeInspectTest` 6 个用例通过（53 断言）。
- `pnpm verify` 全绿。
