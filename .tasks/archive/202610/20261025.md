# fxyin 支持 PHP 8.4

## 背景

风音框架 fxyin（V1.1）声明运行环境 PHP7.1+，被 8 个接入方仓库以 `extend/fxri/base` 源码拷贝方式复用。线上已出现 PHP 8.1+ 的 null 传参弃用告警（`strpos` / `preg_match`），需先在本仓消除 8.4 下的兼容问题，再逐仓铺开。

基线取 fxyin 现状（不先回流下游副本的差异，下游差异另案处理）。改造目标为 7.1 ~ 8.4 双区间可用，不改公有 API 签名与既有语义（如 `get()` 无参返回全量）。

## 实施方案

1. 环境：使用 `<本机>/BtSoft/php/84/php.exe`（8.4.27 NTS），以 `-n -d extension=...` 独立加载扩展验证，不改 BT 面板的扩展开关。
2. 已知缺陷修复：
   - `app/controller/facade/Base.php` `config()`：无参时 `strpos(null, '?')`，与同文件 `env()` 的 `?? ''` 写法对齐。
   - `app/controller/facade/Client.php` `browser()` / `system()`：CLI 无 `HTTP_USER_AGENT` 时 `$echo` 为 null，后续 `strpos` / `preg_match` 传 null，改为空串。
   - `app/controller/facade/Server.php` `branch()`：`fxy_env('base.host')` 在 CLI 为 null，进入后立即转 string。
   - `frame/Env.php`、`frame/Config.php` 的 `has()`：名称为 null 时 `explode` 告警，入口归一（`set()` 的 `explode` 位于 `is_string` 分支内，不会收到 null，未改）。
   - 冒烟新增（静态扫描查不到、仅运行域暴露）：
     - `app/controller/facade/Text.php` `strlen()`：`mb_strlen(null)` 弃用，非字符串时长度取 0（返回值 1002「请输入字符串」保持不变）。
     - `app/controller/facade/Text.php` `ipv4()`：`Client::ip()` 无 `REMOTE_ADDR` 时把 null 传入 `explode`，编码分支入口转 string。
     - `app/controller/facade/Server.php` `branch()`：`branch.store` 无默认分支键时 `Undefined array key`，取值加 `?? null` 兜底。
3. 全量静态扫描：PHPCompatibility（`testVersion 7.1-8.4`）装在仓库外临时目录，按报告逐项修；重点为 null 传内置函数、隐式可空参数、动态属性。
4. 注释签名同步：18 处 `string $x = null` / `int $x = null` 候选中，实际改 14 处为 `?string` / `?int`（3 处 `mixed $x = null` 已含 null、1 处已是 `int|null`，不动）。
5. 文档：README 运行环境要求改为 PHP 7.1 ~ 8.4。

## 完成情况

- 已修门面 5 处：`facade/Base.php` `config()`、`facade/Client.php` `browser()` / `system()`、`facade/Server.php` `branch()` 入口与分支配置取值、`facade/Text.php` `strlen()` / `ipv4()`。
- 已修框架 2 处：`frame/Env.php` `has()`、`frame/Config.php` `has()`。
- 已同步 14 处注释签名与 README 运行环境要求（PHP 7.1 ~ 8.4）。
- 验证：8.4 下 `php -l` 全量 44 个文件通过；PHPCompatibility（`testVersion 7.1-8.4`）全量 44 个文件 0 findings；仓库外冒烟脚本（框架初始化 + Env / Config / Client / Server / Base / Text / Data / Param / Safe 关键路径，`error_reporting=E_ALL`）在 8.4 / 7.3 / 7.1 三个版本下均无告警，调用返回值一致。

## 影响范围

仅本仓 `frame/`、`app/controller/facade/`、README，均为内部实现。不改公有 API 签名，不改变无参取全量的语义。下游项目需另案把改造后的副本覆盖回各自的 `extend/fxri/base`。
