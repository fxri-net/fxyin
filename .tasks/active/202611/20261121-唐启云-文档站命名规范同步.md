# 文档站命名规范同步

> 计划位置：总计划第 8 步（本仓）；前置：toolkit 发布 `fxri-docs-writing` 技能；后继：无

## 背景

本仓文档站需按全局技能 `fxri-docs-writing` 的显示名口径统一：页面标题 = 显示名（标识），已声明 `title` 的页面与 H1 一致，
索引使用完整标题，行内引用使用显示名；侧栏允许短别名，只需指向同一对象且在同一导航分组内唯一。

初步扫描：`docs/` 共 34 页；`adr/0001-v2-parity.md` 的 title 与 H1 不一致（title 少了版本号）；
以 `HTTP API` / `SQL` / `IDE` 等专名开头的 H1 属合理用法，不按标识前置处理。
侧栏短别名与 H1 显示名不一致 4 处，执行时按「同一对象、别名唯一」核对：
`AI 技能` ↔ `AI 技能入口`、`扩展迁移` ↔ `门面扩展`、`对等矩阵` ↔ `v1.6.1 能力对等矩阵`、`决策记录` ↔ ADR 标题。
125 条站内链中未见「xxx 命令」旧写法，链接文案以正常显示名为主，改动集中在 ADR 标题与别名核对。

## 实施方案

1. toolkit 新版发布后加载 `fxri-docs-writing`，逐页核对标题、索引与行内引用。
2. 修正 ADR 页 title/H1 不一致；统一链接文案为显示名（可带「配置参考 ·」等分组前缀），不带标识。
3. 导航保持短显示名，不改结构；只对已声明 `title` 的页面保持 title=H1，不强制补 title。
4. 按本仓发版要求补变更集（如适用）。
5. 提交前跑本仓验收。

## 影响范围

- 文档触达：docs/
- 变更集：按本仓规范
- 说明：不改代码与对外能力

## 验证方式

- 按新规范复核标题与引用，无标识前置与混写
- `pnpm verify` 全量通过（含文档构建）

## 回滚

单提交回退；仅改文档标题与链接文案。
