# 补齐旧令牌与旧密文兼容

延续「补齐视频媒体信息」（见 active/202610/20261028-唐启云-补齐视频媒体信息.md）。复核 `Safe::token` 后发现 v1 令牌无法在 v2 读取。

计划位置：本轮第 4 项；前置：补齐视频媒体信息。

## 背景

- v1 `Safe::token($data, 'encode')` 把数据拼成逗号包裹串，用随机字符补齐到 2 的幂，再走默认口令的 DES-ECB 加密并转十六进制；`decode` 反向还原。
- v2 `Security\Token` 是 `v1.<载荷>.<HMAC>` 新格式，`verify()` 只认新格式，读不了 v1 已签发的令牌。
- v2 `Security\LegacyCipher` 只提供解密，没有加密，无法生成 v1 兼容密文。

## 实施方案

1. `LegacyCipher` 增加 `encrypt(string $plain, string $password)`：与 `decrypt()` 使用同一口令派生与 `des-ede3-ecb`，返回 base64；类注释明确仅供读写 1.x 数据。
2. 新增 `Security\LegacyToken`：`encode(string|array $data, string $password)` 生成 v1 格式令牌；`decode(string $token, string $password)` 还原为原始逗号串，格式非法或解密失败返回 `null`。
3. 口令必须显式传入，不在库内固化弱口令；文档说明 v1 默认口令为 `00000000`。
4. 补测试：新旧兼容往返、数组输入、非法十六进制、奇数长度、空串、错误口令。
5. 更新对等快照与 `docs/security.md`。

## 影响范围

`src/Security/LegacyCipher.php`、`src/Security/LegacyToken.php`（新增）、对应测试、`docs/security.md`、`tests/Parity/legacy-api.json`；不改 `Token` 新格式。

## 验证方式

1. `LegacyToken::encode()` 的结果可被 `decode()` 还原。
2. 非法输入返回 `null` 而不抛异常。
3. `pnpm verify` 全绿。

## 回滚方案

新增方法与类可整体回退；`LegacyCipher::decrypt()` 行为不变。
