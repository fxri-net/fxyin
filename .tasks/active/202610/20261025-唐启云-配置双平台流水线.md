# 配置双平台流水线

> 计划位置：第 5/6 项（批次 B5）　前置：第 3 项

## 背景

现有流水线只有单一平台的 PHP 多版本检查，没有文档站构建与部署，也没有自建代码托管平台的流水线。验收步骤目前内联在流水线配置里，与本地命令是两份清单。

## 实施方案

1. `scripts/verify.mjs`：聚合门禁脚本，步骤为 `composer check` → `pnpm docs:build`，支持 `--skip-code` / `--skip-docs`；步骤清单只此一份，本地与全部流水线共用。
2. `.github/workflows/ci.yml`：PHP 8.2 / 8.3 / 8.4 / 8.5 矩阵，装 PHP 与 Node 后统一调用 `node scripts/verify.mjs --skip-docs`；替换现有 `check.yml`。
3. `.github/workflows/deploy-docs.yml`：构建站点 → 上传 Pages 产物 → 部署；权限 `pages: write`、`id-token: write`，并发组 `pages`，`fetch-depth: 0` 保证最后更新时间准确。
4. `.gitlab-ci.yml`：`test` 阶段跑 PHP 侧门禁，`pages` 阶段用 Node 镜像构建站点并输出到 `public/`；`VITEPRESS_BASE` / `SITE_URL` / `REPO_URL` 走 CI/CD 变量，不写死路径。
5. 删除 `.github/workflows/check.yml`。

## 影响范围

新增门禁脚本与三份流水线配置，删除一份旧配置。不改变 PHP 侧校验项本身，`composer check` 仍是代码门禁的唯一真源。流水线不安装全局 `@fxri/toolkit`，变更集与日志的消费只在维护者本地发版时执行。

## 验证方式

- 本地 `node scripts/verify.mjs` 可跑（本机无 composer 时以分段命令验证 PHP 侧四步）。
- 两份 GitHub 工作流 YAML 语法可解析；矩阵覆盖 8.2–8.5。
- GitLab 配置的阶段、产物路径、部署规则符合 Pages 要求。
- 站点 `base` 在三种部署形态下分别正确（本地 `/`、GitHub `/fxyin/`、自建平台全路径）。
- 归档后跑 `toolkit tasks check`。
