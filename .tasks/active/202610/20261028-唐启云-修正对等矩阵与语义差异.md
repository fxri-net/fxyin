# 修正对等矩阵与语义差异

延续「补齐原始 RSA 与 URL 级 HTTP」（见 active/202610/20261028-唐启云-补齐原始RSA与URL级HTTP.md）。本轮收口逐方法复核结论：修正指向错误目标或状态不实的矩阵项，并补齐仍可落地的语义差异。

计划位置：本轮第 4 项；前置：补齐原始 RSA 与 URL 级 HTTP。

## 背景

逐方法对照 92 个门面、18 个全局函数与 27 个运行时方法后，确认以下映射或状态不成立：

- `Text::strEncode` / `strDecode` 是嵌套数组与查询串互转，矩阵误指 Base64；`strEncodeMerge` / `strDecodeMerge` 是同一能力的递归辅助。
- `Text::strlen` 返回长度校验结果，应指 `Str::isLength` 而不是 `Str::length`。
- `Math::rand($length, 0)` 的首字符保证为字母，`Random::string()` 没有该保证。
- `View::echo` 按类型序列化响应，单一指向 `XmlFormatter` 不成立。
- `Base::env` 读写运行期环境叠加，应指 `Config\Store` 而不是 `.env` 解析器。
- `Server::system` 读 `php_uname()` 识别服务端系统，与按 UA 识别的 `ClientInfo::system` 不同。
- `Data::storeUpperLevel` / `storeLowerLevel` 生成 MySQL 专有递归 SQL，`Data\Hierarchy` 是应用层递归，属覆盖而非直接等价。

## 实施方案

1. `RandomCharset` 增加大小写字母集 `Alpha`；`Random::string()` 增加可选首字符集参数，`Math::rand` 的首字母保证有对应入口。
2. 修正 `tests/Parity/legacy-api.json`：`Text` 四个编解码项、`strlen`、`Math.rand`、`View.echo`、`Base.env`、`Server.system`、`Data` 两项的状态与目标按实际能力改写。
3. 重写 `docs/parity-1.6.1.md` 的分组计数表与运行时表，使「需新增」归零、覆盖项与设计移除项与实际状态一致。
4. 新增 `tests/Parity/MappingTest.php`：逐项断言修正后目标的行为（嵌套编解码、长度校验、首字符集、响应序列化、`env` 叠加、系统族、层级递归）。
5. 复核外部映射文档，去掉与快照冲突的表述。

## 影响范围

`src/Support/RandomCharset.php`、`src/Support/Random.php`、`tests/Parity/MappingTest.php`（新增）、`tests/Parity/legacy-api.json`、`docs/parity-1.6.1.md`、`docs/migration-2.0.md`、`docs/text.md`；不改变既有方法签名，仅新增可选参数与枚举分支。

1. 对等审计通过，计数仍为门面 92、全局 18、运行时 27、语言包 6、配置 4。
2. 矩阵全部条目目标可落地，无 `add` 项。
3. `pnpm verify` 全绿。
