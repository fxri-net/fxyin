# 实现配置、翻译与组合根

> 计划位置：第 3/8 项（批次 B3）　前置：第 2 项

## 背景

旧 `frame/Config.php`、`frame/Env.php` 为全局静态可变状态，且反向依赖门面层（调用 `\fxapp\Param::merge`），出现「内核依赖门面」的倒挂；`Env::load()` 的条件写反，文件存在时反而直接返回。`frame/Lang.php` 同样依赖全局函数。框架没有明确的装配入口，使用者只能靠约定目录与环境变量隐式初始化。

本任务把配置、翻译改为实例化对象，并引入不可变组合根 `Kernel`，让接入方式显式化。

## 实施方案

1. `src/Config/Config`：实例化、只读访问，`get` / `has` / `all` 显式类型；写入只在加载期由 `ConfigLoader` 完成，运行期不可变。
2. `src/Config/ConfigLoader`：负责加载 `config/` 下的 PHP 文件与点号路径展开，不依赖门面层；`src/Config/Environment`：`.env` 解析，取代旧 `Env`，修正「文件存在即返回」的判定错误。
3. `src/Translation/ArrayTranslator` 实现 `symfony/translation-contracts` 的翻译接口；`src/Translation/Loader/PhpFileLoader` 读取语言包，取代 `Lang`。
4. `src/Kernel` 与 `src/KernelBuilder`：`KernelBuilder` 提供 `withConfigDir()`、`withAdapter()`、`withLogger()`、`withHttpClient()`，每次 `with*` 返回新实例，`build()` 产出不可变 `Kernel`。不引入依赖注入容器，装配关系全部写在组合根。
5. 内核不再引用任何门面类，反向依赖彻底切断。

## 影响范围

新增 `src/Config/`、`src/Translation/`、`src/Kernel.php`、`src/KernelBuilder.php` 与对应测试。旧 `frame/Config.php`、`frame/Env.php`、`frame/Lang.php` 本任务不删除，第 8 项任务统一移除。

## 验证方式

- `tests/Config/` 覆盖点号路径读取、缺失键默认值、`.env` 覆盖顺序。
- `tests/Translation/` 覆盖占位符替换与语言包缺失回退。
- `tests/KernelBuilderTest.php` 断言不可变性：`withLogger()` 之后原实例的 logger 不变。
- `composer check` 零失败。
- 归档后跑 `toolkit tasks check`。
