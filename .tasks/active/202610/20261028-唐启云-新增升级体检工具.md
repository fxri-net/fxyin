# 新增升级体检工具

配合 1.x 升级 2.0 指南，为接入方提供只读的项目画像、旧 API 统计与只减不增的基线守卫。

计划位置：本轮第 3 项；前置：版本标签与日志收口；可与升级指南并行，但排在指南之后交付。

## 背景

- 接入方需要先判断自身属于哪类升级路线，再按阶段迁移；仅靠人工检索无法稳定度量进度。
- 本机 13 个接入方仓库可用于校准工具，但本次只做只读验证，不修改、不升级任何接入方仓库。
- 部分接入方已有 `ci/verify.php` 的直连基线守卫，新工具需要兼容「按目录计数、只减不增」的模式。

## 实施方案

1. 新增 `tools/upgrade-inspect.php`，仅依赖 PHP 8.2，只读，不 include 目标项目文件、不执行 Composer：
   - `profile`：识别 PHP 约束、宿主框架与版本、入口形态、Composer 状态、`extend/fxri` 模块、`data` 文件构成、调用量档位与阻塞项。
   - `scan`：统计 `\fxapp\*::` 分域与高频方法、`$echo[n]`、点分模式号、`is_*`、`fxy_*`、`\fxyin\`，输出 Markdown 或 JSON。
   - `baseline --write|--check`：按目录写入或校验基线，超过基线非零退出。
2. `composer.json` 增加 `upgrade:inspect` 脚本。
3. 新增 `tests/Tools/UpgradeInspectTest.php`，运行时生成 ThinkPHP 6、非 ThinkPHP、无 Composer 三类临时项目树，断言画像、计数与基线退出码。
4. 对 13 个接入方仓库只读运行，校准汇总计数与画像分类。

## 影响范围

`tools/upgrade-inspect.php`、`composer.json`、`tests/Tools/UpgradeInspectTest.php`；不改 `src/`，不写入任何接入方仓库。

## 验证方式

1. `composer check` 通过，新增测试全绿。
2. 13 个接入方仓库只读校准：`\fxapp\*::` 合计 6044、`$echo[n]` 2491、点分模式号 1032、`is_*` 325、`fxy_*` 75、`\fxyin\` 219；四类接入形态均可识别。
3. `baseline --check` 二次运行零新增；人为新增一处 `\fxapp\` 调用时非零退出。
4. `pnpm verify` 全绿。

## 回滚方案

工具、脚本与测试为普通提交，`git revert` 即恢复；工具本身不修改目标仓库，无需回滚接入方。
