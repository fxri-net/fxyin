# 实现 Security 层

> 计划位置：第 7/8 项（批次 B7）　前置：第 2 项

## 背景

旧 `app/controller/facade/Safe.php` 的安全默认值不可接受：`crypt` 默认算法 `des-ecb`、默认口令固定为 `00000000`；`md5` 用 `$type` 数字码在 16 位与 32 位之间切换；`Text::uuid` 用 `mt_rand` 作随机源，不满足密码学要求。这些默认值一旦被调用方沿用，等于没有加密。

本任务重建安全层，把弱算法隔离到显式的 legacy 类，新代码默认使用现代算法。

## 实施方案

1. `src/Security/Cipher`：默认 AES-256-GCM，随机 IV 随密文输出，认证标签参与校验；密钥必须显式传入，不提供默认口令。
2. `src/Security/LegacyCipher`：保留 `des-ecb` 与固定口令的旧行为，仅用于解密历史数据，类名与文档明示不适用新数据，且默认口令不再内置，必须由调用方给出。
3. `src/Security/Hash`：`HashLength{Short16, Full32}` 取代 `Safe::md5` 的 `$type`；新代码默认推荐 `password_hash`，`md5` 仅作兼容函数保留并标注强度。
4. `src/Security/Token`：令牌生成与校验，随机源 `random_bytes`，支持过期与一次性消费。
5. `src/Security/Rsa`：密钥对生成、签名、验签与加解密，密钥长度下限 2048。
6. 所有敏感入参使用 `#[\SensitiveParameter]`，异常消息与日志不输出密钥、口令、明文。

## 影响范围

新增 `src/Security/` 全层与对应测试。旧 `app/controller/facade/Safe.php`、`Text.php` 的 `uuid` 本任务不修改，第 8 项任务统一移除。

## 验证方式

- `tests/Security/CipherTest.php` 覆盖加解密往返、篡改密文触发认证失败、同一明文两次加密产生不同密文。
- `tests/Security/LegacyCipherTest.php` 用固定向量验证旧数据可解，并断言未传口令时抛异常。
- `tests/Security/HashTest.php` 断言两种 `HashLength` 的输出长度。
- `composer check` 零失败。
- 归档后跑 `toolkit tasks check`。
