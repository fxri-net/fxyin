# 升级体检补强宿主框架识别

3 个 1.x 样本的宿主框架显示「未识别」，profile 因此缺少宿主上下文，路线建议只能靠体量档位。

计划位置：本轮第 4 项；前置：无。

## 背景

- 这些样本没有 composer.json 或没有 `thinkphp/` 目录，入口在根 `index.php`，现有检测只覆盖 Composer 依赖与 `thinkphp` 目录两种信号。
- 同一批样本中有 2 个非 ThinkPHP 项目（`core/start.php`），需要保证补强后不会把它们误判为 ThinkPHP。

## 实施方案

1. 增加入口文件解析：读取 `index.php` 与 `public/index.php` 中的 `require`/`define` 路径，命中 `thinkphp` 目录或 `start.php` 时判定为 ThinkPHP 并读取版本文件。
2. 增加目录信号：存在 `thinkphp/` 且含 `base.php` 时按目录形态报告；存在 `core/start.php` 时仍判为非 ThinkPHP。
3. 版本读取失败时输出「ThinkPHP（版本未知）」，不臆造版本号。

## 影响范围

`tools/upgrade-inspect.php`、`tests/Tools/UpgradeInspectTest.php`。

## 验证方式

1. 新增用例覆盖「无 composer + 根入口 + thinkphp 目录」与「core/start.php」两种形态。
2. 3 个原先未识别的样本不再显示「未识别」。
3. `pnpm verify` 全绿。

## 回滚方案

回退本次提交即可；仅影响画像输出。
