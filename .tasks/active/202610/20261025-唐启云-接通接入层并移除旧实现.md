# 接通接入层并移除旧实现

> 计划位置：第 8/8 项（批次 B8）　前置：第 3、4、6、7 项

## 背景

前 7 项任务把能力重写在 `src/` 下，旧实现仍在原位：`frame/` 八个内核类、`app/controller/facade/` 十一个门面、`app/function/common.php` 全局函数、`autoload.php` 自研加载器、`config.php`，以及 `app/config/facade.php` 里的三段数字键配置。两套实现并存会让使用者无法判断该用哪套，也让 PHPStan 与扫描范围永远需要豁免清单。

本任务完成收口：提供 ThinkPHP 接入适配，删除旧实现，产出迁移对照表。

## 实施方案

1. `src/Integration/ThinkPHP/`：提供容器绑定与异常处理适配，仅在检测到 ThinkPHP 运行时启用；其余框架通过 `KernelBuilder` 直接装配，不写专用适配。
2. 删除 `app/config/facade.php` 中的 `data.where`、`server.echo.template`、`server.echo.format` 三段数字键配置，整文件随门面层一起移除。
3. 移除 `frame/`、`app/controller/facade/`、`app/function/common.php`、`autoload.php`、`config.php`；`composer.json` 的 PSR-4 成为唯一加载方式。
4. `docs/migration-2.0.md`：逐条列出旧 API 到新 API 的对照，包含 14 个点分模式号到 `Shape` 组合、各数字码到具名枚举、`fxy_echo` 到异常、`data.where` 到 `WhereBuilder`；并给出接入方 `extend/fxri/data` 目录的处置分类——上收到框架、保留差异迁入项目配置、项目侧改写机制、直接删除四类，逐项标注归属。
5. `README.md` 更新为 2.0 安装与装配说明，写明 `composer require fxri/fxyin` 与 `KernelBuilder` 最小示例。

## 影响范围

删除旧目录与旧配置，新增接入适配、迁移文档，改写 README。这是 2.0 唯一的破坏性收口点，`src/` 内各层接口在前序任务已定稿，本任务不改其签名。

## 验证方式

- 全仓检索旧门面类名与 `fxy_echo`、`fxy_config`、`fxy_lang` 等全局函数，除迁移文档与归档记录外归零。
- `composer dump-autoload` 后 `Fxri\Kernel` 可实例化，`KernelBuilder` 最小示例可跑通。
- `composer check` 零失败，扫描范围不再需要 `src/` 之外的豁免。
- 归档后跑 `toolkit tasks check`。
